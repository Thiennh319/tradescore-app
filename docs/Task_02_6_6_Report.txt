PHẦN 2 — EXECUTION MODEL
================================================================================

interface RuntimeExecutorContext {
  runtimeDispatcherResult: RuntimeDispatcherResult
  scanId?: string
}

interface RuntimeExecutorResult {
  runtimeDispatcherResult    // passthrough
  executionPlan
  executionCount
  halted
  message
  context
}

interface RuntimeExecutionItem {
  executionId
  dispatchId
  actionId
  executionOrder
  executionStatus
  metadata                     // actionType, fromState, toState, reason, dispatchStatus
}

enum RuntimeExecutionStatus {
  READY
  SKIPPED
}

Không có RUNNING / SUCCESS / FAILED / TIMEOUT / RETRY / CANCELLED.

executionId format: EXECUTION-001, EXECUTION-002, ... (deterministic)

================================================================================
PHẦN 3 — EXECUTION FLOW
================================================================================

  validateRuntimeExecutorContext()
        ↓
  buildExecutionPlan()
        ↓
  validateRuntimeExecutorResult()
        ↓
  return RuntimeExecutorResult

buildRuntimeExecutorResult(context) — entry point.

Rules:
  • Mỗi RuntimeDispatchItem → đúng 1 RuntimeExecutionItem
  • dispatchStatus SKIPPED → executionStatus SKIPPED
  • dispatchStatus QUEUED → executionStatus READY
  • executionOrder giữ nguyên
  • executionCount = executionPlan.length
  • Không reorder / scheduler / execute
