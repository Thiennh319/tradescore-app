## 5. SPEC BƯỚC 3 (Entry Quality Engine)

### 5.1 — Copy nguyên văn từ `docs/V4.1_ARCHITECTURE.md`

## Bước 3 — Opportunity Detection Layer

**Điều kiện chạy:** `visibility_mode ∈ { TRADE_MODE, POSITION_MODE }`

| | Chi tiết |
|---|----------|
| **INPUT** | • `MarketIntelligenceSnapshot` |
| | • `visibility_mode` |
| | • `ProtectionSnapshot` (Bước 6) — optional filter |
| | • `symbol`, `mark_price` |
| **OUTPUT** | • `buy_score` (number, 0–100) |
| | • `sell_score` (number, 0–100) |
| | • `entry_quality` (number, 0–100) |
| | • `opportunity_direction` (enum: `LONG` \| `SHORT` \| `NONE`) |
| | • `opportunity_valid` (boolean) — true nếu `entry_quality ≥ 70` |

> Ngưỡng `entry_quality ≥ 70` là gate vào Bước 4 (theo spec kiến trúc V4.1).

### ENTRY QUALITY ENGINE — CÔNG THỨC (Bước 3)

**Input:** `MarketIntelligenceSnapshot` (Bước 1) + `ProtectionSnapshot` (Bước 6)

#### Bước A — Direction Score (0–30 điểm)

Xác định điểm hướng **riêng** cho Long và Short (không gộp một điểm chung) — một coin có thể tốt cho Long nhưng tệ cho Short.

**`direction_score_long`** (dùng khi tính entry quality phía Long):

| Điều kiện | Điểm |
|-----------|------|
| `trend_direction = BULL` | +15 |
| `market_state ∈ { Strong Uptrend, Healthy Uptrend }` | +15 |
| `market_state = Late Uptrend` | +8 |
| `market_state` khác (Distribution, Weak Downtrend, Strong Downtrend, Accumulation, Transition) | +0 |

**`direction_score_short`** (đảo ngược logic cho Short):

| Điều kiện | Điểm |
|-----------|------|
| `trend_direction = BEAR` | +15 |
| `market_state ∈ { Strong Downtrend, Weak Downtrend }` | +15 |
| `market_state = Distribution` | +8 |
| `market_state` khác (Strong Uptrend, Healthy Uptrend, Late Uptrend, Accumulation, Transition) | +0 |

> Cộng dồn các dòng khớp (tối đa 30 cho mỗi hướng).

#### Bước B — Confidence Score (0–30 điểm)

Lấy trực tiếp từ `MarketConfidence` (Engine 4), quy đổi tuyến tính — **cùng giá trị cho cả hai hướng** (không phân biệt Long/Short):

```
confidence_score = MarketConfidence × 0.3
```

(`MarketConfidence` thang 0–100; trọng số 30%.)

#### Bước C — Reversal Risk Penalty (0 đến −20 điểm)

Chỉ áp dụng khi hướng đang xét **ngược** với tín hiệu đảo chiều — **phạt**, không cộng điểm hướng nào.

| Đang xét | Điều kiện | Penalty |
|----------|-----------|---------|
| Long (`buy` path) | `ReversalProbability ≥ 60` **và** `market_state ∈ { Late Uptrend, Distribution }` | **−20** |
| Short (`sell` path) | `ReversalProbability ≥ 60` **và** `market_state = Accumulation` | **−20** |
| Khác | — | **0** |

> Logic: đang mua nhưng xác suất đảo chiều cao + đang ở cuối uptrend / phân phối → phạt; đang bán nhưng tích lũy đáy → phạt.

#### Bước D — Protection Penalty (0 đến −20 điểm)

Từ `ProtectionSnapshot` — hai điều kiện **độc lập**, cộng dồn:

| Điều kiện | Penalty |
|-----------|---------|
| `stop_hunt_detected = true` | **−10** |
| `volatility_risk = EXTREME` | **−10** |

Tối đa **−20** (cả hai cùng lúc).

#### Tổng hợp `entry_quality` (theo từng hướng)

```
raw_long  = direction_score_long  + confidence_score + 40
raw_short = direction_score_short + confidence_score + 40
```

(`40` = điểm sàn mặc định — “có cơ hội nhưng chưa xác nhận”.)

```
entry_quality_long  = clamp(0, 100, raw_long  + reversal_penalty_long  + protection_penalty)
entry_quality_short = clamp(0, 100, raw_short + reversal_penalty_short + protection_penalty)
```

**Ánh xạ OUTPUT (giữ contract bảng trên):**

| Field OUTPUT | Giá trị |
|--------------|---------|
| `buy_score` | `entry_quality_long` |
| `sell_score` | `entry_quality_short` |
| `entry_quality` | điểm của hướng được chọn (`opportunity_direction`) |
| `opportunity_direction` | Xem bên dưới |
| `opportunity_valid` | `true` nếu `entry_quality` (hướng chọn) **≥ 70** |

**Chọn hướng:**

```
if entry_quality_long < 50 AND entry_quality_short < 50:
  opportunity_direction = NONE
elif entry_quality_long > entry_quality_short:
  opportunity_direction = LONG
elif entry_quality_short > entry_quality_long:
  opportunity_direction = SHORT
else:  # hòa
  opportunity_direction = NONE
```

`entry_quality` = `entry_quality_long` hoặc `entry_quality_short` tương ứng với `opportunity_direction` (khi `NONE` → `entry_quality = max(long, short)` cho hiển thị, `opportunity_valid = false`).

#### Ví dụ số

| Input | Giá trị |
|-------|---------|
| `TrendStrength` | 80 |
| `trend_direction` | BULL |
| `market_state` | Healthy Uptrend |
| `MarketConfidence` | 72 |
| `ReversalProbability` | 30 |
| `stop_hunt_detected` | false |
| `volatility_risk` | NORMAL |

**Long path:**

- Direction: BULL (+15) + Healthy Uptrend (+15) = **30**
- Confidence: 72 × 0.3 = **21.6**
- Reversal penalty: 30 < 60 → **0**
- Protection penalty: **0**
- raw = 30 + 21.6 + 40 = **91.6** → `entry_quality_long` = **92** (làm tròn)

**Short path:**

- Direction: không BEAR, không khớp state Short → **0**
- Confidence: **21.6**
- Penalties: **0**
- raw = 0 + 21.6 + 40 = **61.6** → `entry_quality_short` = **62**

→ `opportunity_direction = LONG` (92 > 62), `entry_quality = 92`, `opportunity_valid = true` (92 ≥ 70).

#### Bảng phân loại (theo spec gốc mục 5)

| `entry_quality` | Phân loại |
|-----------------|-----------|
| 0–30 | No Trade |
| 30–50 | Watchlist |
| 50–70 | Setup Forming |
| 70–85 | Trade Ready |
| 85–100 | High Quality Entry |

## 6. SPEC BƯỚC 4–7 (tóm tắt)

### Bước 4 — Risk → Profit → Trade Setup

Chạy khi `opportunity_valid === true` (`entry_quality ≥ 70`). **Risk Engine** tính Smart SL từ MI snapshot + Protection + direction. **Profit Engine** tính TP1–3 từ khoảng cách SL. **Trade Setup Generator** gom `TradeSetupV41` (entry zone, SL, TP, margin, leverage). Chưa có file implementation.

### Bước 5 — Position Management

Chạy khi `position_state.has_open_position === true`. Đọc **MI snapshot scan hiện tại** (không snapshot lúc entry) + Protection + open position → advisor action (HOLD, CLOSE, BE, trailing…). Chưa có `positionAdvisorV41`.

### Bước 6 — Protection Layer

Chạy song song sau Bước 0; chỉ cần `symbol_klines`. **Stop Hunt Detector** (wick ratio + nến xác nhận) và **Volatility Risk** (`atr_ratio = ATR14 / SMA(ATR14,50)`). Output `ProtectionSnapshot` — input phụ cho Bước 3 penalty và Bước 4 SL.

### Bước 7 — Support System

Async sau ENTER/CLOSE — journal persist, analytics, cooldown. Không nằm critical path scan. Có thể tái sử dụng journal V3/V4 hiện có cho V4.1 entries sau này.
