PHẦN 2 — WHY currentState INFERENCE WAS REMOVED
================================================================================

UL-01 originally derived currentState:

  FinalEntryStatus → mapFinalEntryStatusToStateMachine() → StateMachineEntryState

This mixed transport with business semantics. Problems:

  1. Bridge inferred runtime state from scan-time gate (FinalEntryStatus)
  2. LOCKED and other states cannot be derived from FinalEntryStatus alone
  3. Store bridge (UL-02+) must own persisted ESM state — not the mapper
  4. EntryStateMapping bridge remains available for explicit callers outside
     transport layer

New rule (transport only):

  IF input.currentState provided → use caller value
  ELSE → ORCHESTRATOR_DEFAULT_CURRENT_STATE (WATCH)

Evidence: signalRowMapper.ts resolveCurrentState() — no imports of
mapFinalEntryStatusToStateMachine or resolveFinalEntryStatus.

Regression test: productionEsmBridge.test.ts
  "defaults currentState to ORCHESTRATOR_DEFAULT_CURRENT_STATE — no FinalEntryStatus inference"
  "does not infer currentState from WAIT_ENTRY finalEntryStatus"

================================================================================
PHẦN 3 — WHY TriggerSnapshotFactory WAS INTRODUCED
================================================================================

UL-01 hardcoded triggerSnapshot: {} inside signalRowMapper.

Problems:

  1. Bridge owned trigger snapshot semantics inline
  2. Future detector integration would require editing mapper logic
  3. No single SSOT for "empty production trigger bundle"

Solution:

  triggerSnapshotFactory.ts
    CANONICAL_EMPTY_TRIGGER_SNAPSHOT  — frozen canonical definition
    createEmptyTriggerSnapshot()      — factory entry point
    TriggerSnapshotFactory namespace

Mapper calls createEmptyTriggerSnapshot() only — does not know detector internals.

Future UL tasks replace factory implementation (or add createProductionTriggerSnapshot)
without changing mapSignalRowToWiringContext transport logic.
