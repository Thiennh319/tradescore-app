PHẦN 3 — STORE ARCHITECTURE
================================================================================

useTradeStore
  └── esmBridge (dedicated namespace — no loose global fields)
        ├── latestSnapshot: ProductionEsmBridgeSnapshot | null
        ├── lastUpdated: number | null
        ├── enabled: boolean  (from snapshot.entryStateManagerEnabled)
        └── status: 'idle' | 'stored' | 'skipped'

Write flow:

  ProductionEsmBridge.runProductionEsmBridge()
        │
        ▼
  writeEsmSnapshotToStore(snapshot, store)
        │
        ▼
  store.updateEsmSnapshot(snapshot)
        │
        ▼
  esmBridge namespace updated (deep copy via structuredClone)

Read flow (future UL-03 UI):

  useTradeStore(s => s.esmBridge)
        │
        ▼
  latestSnapshot → display only

================================================================================
PHẦN 4 — SNAPSHOT LIFECYCLE
================================================================================

1. idle — initial state, latestSnapshot = null
2. Caller runs runProductionEsmBridge (explicit — NOT automatic from scan)
3. writeEsmSnapshotToStore validates + calls updateEsmSnapshot
4. Store deep-copies snapshot into esmBridge.latestSnapshot
5. lastUpdated set (injectable now for tests)
6. status = 'stored' if entryStateManagerEnabled, else 'skipped'
7. Subsequent write overwrites latestSnapshot (single-slot SSOT)
8. No disk persistence in UL-02 (in-memory only — no hydrate change)

Valid when ENTRY_STATE_MANAGER_ENABLED OFF:
  harnessResult = null, status = 'skipped', enabled = false

================================================================================
PHẦN 5 — WHY STORE CONTAINS DATA ONLY
================================================================================

updateEsmSnapshot:
  - Validates snapshot shape (validateStorableEsmSnapshot)
  - Deep-copies via structuredClone
  - Sets namespace fields from snapshot metadata only

Store does NOT:
  - Call runEntryStateManagerPipeline
  - Map FinalEntryStatus → EntryState
  - Evaluate triggers or recommendations
  - Invoke Position Adviser
  - Render UI

Business logic remains in frozen ESM (entryStateManager) when explicitly
invoked by ProductionEsmBridge before write.

================================================================================
PHẦN 6 — WHY BUSINESS LOGIC STAYS INSIDE ESM
================================================================================

Separation of concerns (UL-01.1 → UL-02):

  productionEsmBridge/  — transport + optional pipeline invoke
  entryStateManager/    — frozen evaluation pipeline (when flag ON)
  store/esmBridge       — passive snapshot retention
  future UI (UL-03)     — read-only display

Store is SSOT for *stored snapshots*, not for *computing* ESM outcomes.
