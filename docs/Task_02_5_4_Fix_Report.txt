PHẦN 2 — FIX 1: RESOLUTION QUA POLICY
================================================================================

VẤN ĐỀ
------
resolveConflictGroup() trực tiếp:
  - getPriorityForKind() per member trong resolver
  - Math.max(...)
  - filter theo priority

GIẢI PHÁP
---------
Chuyển toàn bộ winner logic vào CONFLICT_RESOLUTION_POLICY:

  resolveByCatalogPriority(members) → CatalogPriorityResolutionOutcome
  getWinningTrigger(members)        → delegates resolveByCatalogPriority

Policy là module duy nhất đọc TRIGGER_TYPE_CATALOG cho resolution.

resolveConflictGroup() — thin wrapper:

  const outcome = CONFLICT_RESOLUTION_POLICY.resolveByCatalogPriority(group.members);
  return { groupId, conflictKind, ...outcome };

ConflictResolver KHÔNG còn Math.max / so sánh priority trực tiếp.

PHẦN 3 — FIX 2: resolvedBy
================================================================================

enum ConflictResolutionMethod {
  CATALOG_PRIORITY
  SAME_PRIORITY
}

ResolvedConflict — thêm field (backward-compatible extension):

  resolvedBy: ConflictResolutionMethod | null

Quy tắc:
  | Tình huống                    | resolvedBy        |
  |-------------------------------|-------------------|
  | Unique catalog priority winner| CATALOG_PRIORITY  |
  | Same priority tie             | SAME_PRIORITY     |
  | Insufficient members          | null              |

Không parse từ reason — set trực tiếp trong Policy.

Ví dụ:
  HardBlock vs Confirmation → CATALOG_PRIORITY
  Recovery vs Unlock        → SAME_PRIORITY
